# 00 学习路径与项目速览(索引)

> **这是什么**:`docs/learning/` 是一套围绕 [Pharos](../../README.zh.md) 写的**RAG 学习 + 面试冲刺**文档。不是 API 手册,也不是运维指南(那些在 [../OVERVIEW.md](../OVERVIEW.md) 与 [../OPERATIONS.md](../OPERATIONS.md));它是把一个**真做过、被数据反复打脸又修正过**的 agentic RAG 系统,拆成 10 篇教学,让你既学透 RAG 每一层的取舍,又能在面试里连续应对 20 分钟追问。
> **读者**:想把 RAG 从"会调包"学到"讲得出为什么"、并准备用这个项目做简历主项的工程师。
> **本篇是地图**:先读这里,选一条读法,再进正文。

## 一、这套文档是什么、怎么读

**10 篇正文(01–10)同构,每篇都是七到八个固定板块**,你可以直接跳到你要的那块:

| 板块 | 干什么 | 面试用途 |
|---|---|---|
| **1. 概念底座** | 这一层在**任何** RAG 里解决什么问题、朴素做法为什么摔跤 | 答"这个环节是什么" |
| **2. Pharos 怎么做** | 本项目的真实实现 + 数据流 | 答"你怎么做的" |
| **3. 为什么这么设计** | 被**否决**的备选 + 否决它的实测数据 | 答"为什么不用 X" |
| **4. 实战复盘** | 真 bug 的症状 → 根因 → 修法 → 证据 | 讲故事的弹药 |
| **5. 面试怎么讲** | 30 秒 / 3 分钟话术 | 直接背 |
| **6. 追问预演** | 面试官会怎么追、关键词是什么 | 抗压 |
| **7. 动手实验** | CPU 零依赖 / GPU 真库两档 lab | 把"讲得出"变"做得出" |
| **8. 诚实边界** | 主动交出的弱点清单 | 主动认弱点比被挖出来强 |

**一条贯穿全套的纪律 —— 数据只报真值、口径分档标注**。同一个"忠实度"在不同评测线上是不同的数(88 题 DeepSeek 裁判 vs 72 题双 Claude 裁判),本套文档**从不混用**,每个数字都带口径。凡涉及 agentic 净负结论,一律带 `eval#0 组装偏置待重评` 的 caveat。全局口径见[第六节速查卡](#六全局数据速查卡)。

## 三、一分钟看懂 Pharos

> 亚历山大灯塔守在图书馆旁为航船指路;Pharos 为团队的文档库导航。

**是什么**:自包含单仓的多格式 agentic RAG 系统。把 PDF / 扫描件 / docx / pptx / xlsx 变成**能问答、带企业级 ACL、可溯源引用**的本地知识库(单卡 4090)。一个守护进程,**双出口共用同一检索引擎**:

```
索引侧:  文件 ─parse(MinerU)─► Element[] ─chunk─► Chunk[] + heading 骨架 ─embed─► Qdrant + sidecar
查询侧:  问题 ─encode─► hybrid 召回(dense + BM25, RRF) ─► rerank(可选) ─► ACL 硬过滤
              ─► 查询期 small-to-big(取包围区) ─► generate(LLM + grounding + [cite:n]) ─► 带引用答案
贯穿:    ACL fail-closed 从 chunk 盖章一路守到生成出口;评估闭环量化每一步
```

- **闭管道**(`pharos serve` → HTTP `/v1/ask`):一问一答、确定性、可评估 —— **默认推荐**(评估证明它最好最省)。
- **agentic**(`pharos mcp` → 6 个 MCP 工具):检索引擎暴露成工具,agent(如 Claude Code)自驱多跳。

**已投产**:生产库 ≈ **77 篇真文档 / 7652 chunk**;经 88 题去偏评估 + 五批对抗复审(R1–R5)加固;已完成单机 → 三层可扩缩(阶段 A–F)的多副本改造。当前 v0.3.0。

## 四、项目讲述三档话术

三档由短到长,越往下越展开;每档都标了**接得住的深挖跳转**,面试官挑哪个方向你都有整篇弹药。

### 30 秒 · 简历 / 电梯版

> 我做了 Pharos,一个多格式 agentic RAG 系统:把 PDF、扫描件、Office 文档变成能问答、带企业级权限控制、可溯源引用的本地知识库,在单卡 4090 上服务小团队。两种消费模式——HTTP 闭管道问答和 MCP 工具面(给 Claude Code 这类 agent 自驱检索)。跟一般 RAG demo 不一样的就是这三点:**权限过滤下推到召回层做到 fail-closed;一套异厂裁判的去偏评估闭环,实测忠实度接近 1.0;所有关键决策都有被否决的备选和数据——包括用实测推翻了"agentic 一定更好"的直觉(方向已立、幅度带 eval#0 待重评 caveat)**。

→ 三个卖点分别深挖:权限 [04](04-acl-security.md) · 评估 [07](07-evaluation.md) · agentic 净负 [06](06-agentic-mcp.md)。

### 3 分钟 · 自我介绍版(问题 → 架构 → 数据 → 方法论)

1. **问题**(~30s):团队文档库要能问答,但朴素 RAG 有一串坑——解析失真、切块破坏语义、单路召回盲区、图表检索不到、权限裸奔、生成编造、改了不知好坏。我按这个**问题谱系**逐个给答案(见 [01](01-rag-overview.md))。
2. **架构**(~60s):索引侧 MinerU 统一解析五种格式,chunker 重建 heading 树、切小块、盖 ACL 章;查询侧 dense+BM25 双路 RRF 融合、ACL filter 下推到每路 prefetch、small-to-big 组装大块喂 LLM、`[cite:n]` 引用保溯源。整个跑在一个守护进程里(嵌入式 Qdrant 独占锁 + 8B 模型加载 1–2 分钟**决定了必须常驻**),双出口共用同一套工具语义、不漂移(见 [08](08-service-architecture.md))。
3. **数据**(~45s):生产库 77 篇 / 7652 chunk;88 题评估集,程序化三指标 + 异厂裁判两指标(合计五指标)。**忠实度 ≈1.0——系统宁可拒答不编造;单跳正确性 0.97**(72 题口径)。最反直觉的结论:paired 归因显示 agent 自驱多跳比闭管道正确性低约 0.1(Δ−0.097;**幅度带 eval#0 组装偏置 caveat、待重评,方向未被推翻**),所以闭管道才是默认(见 [07](07-evaluation.md))。
4. **方法论**(~45s):每个组件封板前做对抗 review,全栈再做五批系统性复审,**揪出过评估管道自身的 bug**——裁判 context 被截断,凭空造出"17% 幻觉"的假结论,重判后订正到 ≈1.0。这件事让我对"评估基建先于优化"有了肌肉记忆(见 [10](10-methodology-stories.md))。

> 收尾留钩子:"权限、评估、扩展性三个方向都有完整深挖故事,您挑哪个我都能接。"

### 15 分钟 · 深挖版(白板级 agenda)

当面试官说"多讲讲",按这条线走,每站都能停下来展开、接住追问。目标是**用一个真项目串起 RAG 的完整取舍链 + 一次诚实的自我推翻**。

| 分钟 | 讲什么 | 落到哪篇 | 一定要抛的"钩子事实" |
|---|---|---|---|
| 0–2 | 项目定位 + 六环节数据流(白板画上面那张图) | [01](01-rag-overview.md) | 双出口共用一个引擎;为什么必须是守护进程 |
| 2–4 | 切块:heading 树多信号重建 + small-to-big | [02](02-parsing-chunking.md) | **66.6ms 实测杀死自己的 lazy 设计**;reset-aware 裸编号提级 |
| 4–7 | 检索:hybrid RRF + rerank + 图文同空间 | [03](03-retrieval.md) | RRF 只用名次零超参;hybrid 0.541>dense 0.510>BM25 0.449;rerank 0.566→0.867 |
| 7–9 | 权限:三道闸 fail-closed | [04](04-acl-security.md) | **嵌入式 fusion 丢顶层 should 的 fail-open**;禁出口闸仍 0 召回 |
| 9–11 | 生成:`[cite:n]` + grounding 三层 + ③ 表格数值 | [05](05-generation-grounding.md) | 表格数召回到却答不出的**双重丢失根因链** |
| 11–13 | 评估:去偏三角 + 忠实度假结论故事 | [07](07-evaluation.md) | **0.83 假幻觉是评估管道自己的 bug**;配对归因;口径断代 |
| 13–15 | 反直觉结论 + 扩展性 + 诚实边界 | [06](06-agentic-mcp.md) · [09](09-scale-out.md) | agentic 净负 Δ−0.097(**带 eval#0 待重评 caveat**);吞吐上界=单卡 GPU 串行 ~3.2 req/s |

> 深挖版的杀手锏是**主动认弱**:cross-doc 综合 0.00(n=5)、合成 gold 同源偏置、agentic 幅度存疑——每篇的"诚实边界"节就是这份供词。面试里主动交出比被挖出来强得多。

## 六、全局数据速查卡

> **口径铁律**:下面每个数字都标了来源评测线,**不同线的数字不可直接比较**。两条主线并存:
> - **Tier1** = `--judge deepseek`,**88 题**(72 散文 + 16 表格),仓内可复现、同厂趋势。
> - **Tier2** = 双 Claude 权威裁判,**72 题**口径(早于表格扩充),R5 订正,不入仓可复现。
> 88 vs 72 是**口径断代**,并存、各自标注,严禁混用。

### 端到端五指标(闭管道 single 为准)

| 指标 | Tier1(88 题 · DeepSeek 裁判) | Tier2(72 题 · 双 Claude 裁判) |
|---|---|---|
| 忠实度 | 0.977 | **≈1.000** |
| 正确性 | 0.818 | 0.847 |
| 检索召回 | 0.818 | 0.854 |
| 引用正确 | 0.767 | —(Tier2 未单列) |
| MRR | 0.627 | —(Tier2 未单列) |

- **忠实度是头号卖点**:系统宁可答"无相关信息"也不编,`[cite:n]` 可溯源。⚠ 早先曾报 0.83,R5 查实是**评估管道自身 bug**(裁判 context 被截断只看到 40%),喂全 context 重判订正到 ≈1.0(见 [07 §4.1](07-evaluation.md))。

### 按 hop 拆分的正确性(72 题口径)

| hop 类型 | 正确性 | 备注 |
|---|---|---|
| single-hop | **0.97** | 最强项:单篇事实、表格数值 |
| 单篇多跳(multi_intra) | 0.83 | |
| 跨文档多跳(multi_cross) | **0.00** | ⚠ **n=5,仅方向信号**;瓶颈是综合不是检索,研究性难题未追 |

### 双层归因(paired,72 题口径)

| 对比 | Δ 正确性 | caveat |
|---|---|---|
| single → agentic | **−0.097** | ⚠ **`eval#0` 组装偏置待重评**:agentic 路径的 context 少装了两个生产修复(表格 content_raw / 面包屑),**幅度存疑,方向暂无推翻证据** |
| single → decompose | −0.014 | 同上 caveat 适用 |

> 引用 agentic 净负结论时**必须**带上 eval#0 caveat——这是本套文档的硬规则。

### 组件级评测(合成集,**趋势可信、绝对值仅参考**)

| 项 | 数字 | 口径 |
|---|---|---|
| hybrid vs 单路召回 | hybrid **0.541** > dense 0.510 > BM25 0.449 | 合成集趋势 |
| rerank 增益 | 0.566 → **0.867** | 合成集,精排开关 |
| 自研切块 vs chonkie | ours **79.5%** vs 74.9% | 护城河=工程集成非边界算法 |
| eager 全树重建耗时 | **66.6ms** | 实测否决了"lazy" |
| 图文同空间相似度 | 描述↔对应图 0.74 / 0.49 | 纯图 chunk 可被文字召回 |
